## Fix these first (топ-5 по серьёзности × вероятности × бизнес-эффекту)

1. **`assets/car-page.js` не передаёт `isLeaseProgram` в заявку, хотя `index.html` и
   `catalog.html` передают.** Подтверждено вживую: `index.html:1634` и
   `catalog.html:1693` шлют `isLeaseProgram: !!car.isLeaseProgram`, `car-page.js`
   (та же логика, другая копия формы) — нет такого поля вообще. Это не теория, это
   уже расходящийся payload **прямо сейчас**, на всех 68 индивидуальных страницах
   машин — самых посещаемых SEO-страницах сайта. Если Worker/CRM использует этот
   флаг для маршрутизации лизинг vs аренда — заявки с карточек машин могут
   классифицироваться неверно. **Что сломается, если не чинить:** тихая потеря
   данных о типе сделки на самом трафикогенерирующем типе страницы.

2. **XSS: название машины вставляется в `innerHTML` после декодирования атрибута.**
   `assets/car-page.js:180`. `generate_cars.py` экранирует `title_attr` при записи
   в HTML-атрибут `data-car`, но браузер декодирует атрибут при чтении
   `btn.dataset.car` — экранирование не переживает это декодирование. Результат
   конкатенируется в `modal.innerHTML = ... + opts.carTitle + ...` без повторного
   экранирования. **Что сломается:** если в названии машины когда-либо окажется
   `<`/`>` (копипаст с сайта дилера, опечатка) — выполнится как HTML/скрипт у
   каждого посетителя. Дешёво чинится (`textContent` вместо конкатенации).

3. **`generate_cars.py`: описание машины не экранируется, хотя атрибуты — да.**
   Подтверждено: `title_attr = html.escape(car_title(car))...` используется для
   HTML-атрибутов (строки 1547, 1603), но `render_description()` (строка ~1380-1400)
   вставляет `title`/`spec`/`komplekt` в `<p class="dl-description">` без единого
   вызова `html.escape()`. Непоследовательность — где-то экранируют, где-то нет.
   Тот же класс риска, что и находка 2, но на уровне генератора — затрагивает
   все сгенерированные страницы машин.

4. **Повторяющийся `art` молча перезатирает страницу другой машины.**
   Подтверждено: `slugs_by_art[c['art']] = slug` в простом словаре без проверки на
   дубликат (`generate_cars.py:1911`). Сейчас дубликатов `art` в данных нет (проверил
   по всем 68 записям) — это мина, не действующий баг. Но правило самого репо
   (`AGENTS.md` п.2) прямо предупреждает: "иначе страницы машин разъедутся с
   каталогом молча" — именно это и произойдёт, если дубликат появится.

5. **Проданные/удалённые машины остаются опубликованными навсегда.**
   Подтверждено: в `generate_cars.py` нет ни одного вызова `os.remove`/`rmtree` —
   скрипт только создаёт/обновляет `cars/<slug>/`, никогда не удаляет. Страница
   машины, убранной из каталога, продолжает висеть в индексе поисковиков и
   отдаваться по старому URL бесконечно — SEO-мусор и потенциально вводящая в
   заблуждение страница ("в наличии", хотя давно продана).

## Принятые риски (сводка с условием пересмотра)

- Аналитика грузится до cookie-уведомления — пересмотреть при появлении EU-трафика/юр.требования.
- Нет тестовой инфраструктуры в принципе (4 находки об этом) — это отдельный проект
  уровня "завести тесты", не точечные фиксы. Пересмотреть, когда будет бюджет на это направление.
- Клиент отправляет цену в Worker — зона ответственности Worker, не этого репо. Пересмотреть
  при следующей работе над самим Worker.
- `CARS` как regex-парсимый JS-литерал вместо JSON — архитектурный выбор, работает сейчас.
  Пересмотреть при следующем touch формата данных.
- Неатомарная сборка сайта — пересмотреть, если сборка хоть раз реально упадёт на середине.
