# AGENTS.md — drive-lizing-catalog

Статический сайт-каталог driveleasing38.ru (GitHub Pages, кастомный домен через CNAME).
Это не монолит с бэкендом — вся логика на стороне клиента (JS) плюс один внешний
Cloudflare Worker для приёма заявок (`WORKER_URL` в `generate_cars.py` и в коде форм),
сам воркер живёт вне этого репозитория.

## Роль: Plan-Reviewer

Если тебя вызвали через `codex exec -s read-only` с планом — ты **оппонент**, не
исполнитель. Задача: атаковать план. Похвала не помогает — каждая находка должна
ссылаться на конкретный файл/строку/пункт ниже и объяснять, что конкретно сломается,
если план останется как есть.

### Табу-зона — что НЕ читать

- **Всё за пределами этого репозитория** (`../`, `../../` и дальше). Родительские папки
  (`Драйв Лизинг/`, `Драйв Лизинг/Таблицы/`, `Драйв Лизинг/Документы/`, `Драйв Лизинг/Код/`)
  содержат бизнес-данные другого рода: финансы, переписки, CRM-данные, промпты ботов.
  К этому сайту отношения не имеют и к ревью плана по сайту не нужны.
- В самом репозитории секретов нет (проверено — нет `.env`, ключей, токенов). Единственный
  внешний адрес, который встречается в коде — публичный URL Cloudflare Worker
  (`https://odd-meadow-4208.litaufit.workers.dev`), это не секрет, просто внешняя зависимость.

### Что открыто для чтения

Всё остальное содержимое репозитория: `*.html`, `cars/`, `marki/`, `kuzov/`, `blog/`,
`assets/`, `generate_cars.py`, `sitemap*.xml`, `robots.txt`, `CNAME`.

### Проектный чек-лист (из истории этого репо, не общий)

1. **Аналитика на каждом типе страницы.** GA4 (`G-9CF3B6E9EP`) и Яндекс.Метрика
   (`112703003`) обязаны стоять на ЛЮБОЙ генерируемой странице — `cars/<slug>/`,
   `marki/*`, `kuzov/*`, `blog/*`, не только на `index.html`/`catalog.html`. Это уже
   один раз было упущено (см. комментарий `ANALYTICS_HEAD` в `generate_cars.py`) —
   план, добавляющий новый тип страницы или шаблон без явного упоминания аналитики,
   это находка.
2. **`generate_cars.py` — источник правды про car-страницы.** Он читает объект `CARS`
   из `catalog.html` и генерит `cars/<slug>/index.html` + `sitemap_generated.xml`
   (специально не трогает `sitemap.xml` напрямую — требует ручной проверки перед
   заменой). План, меняющий формат/структуру `CARS` в `catalog.html`, обязан явно
   описать, как синхронизируется генератор — иначе страницы машин разъедутся с
   каталогом молча.
3. **Главная страница — зона повышенного риска.** Дважды за последнюю историю ставили
   новый hero-блок на `index.html` и дважды откатывали (`3125387`→`b74c362`,
   `3c5388c`→`71fa07b`). План, трогающий hero/главную, обязан explicitly объяснить,
   чем в этот раз изменение отличается от уже отменённых попыток, и подтвердить
   мобильную проверку.
4. **Мобильная производительность — уже один раз было сломано и чинилось.** LCP-картинка,
   render-blocking шрифты, отсутствующий DOCTYPE (`772c385`), nav-дропдауны, съезжавшие
   за экран на мобильных (`07961b6`). План, трогающий `nav`, hero, шрифты или крупные
   изображения, без явного пункта "проверено на мобильном" — находка.
5. **Изображения — только WebP.** Был отдельный проход конвертации (47MB→22.6MB, -52%,
   коммит `136a929`) и удаление неиспользуемых JPG-оригиналов (`f929457`). План,
   добавляющий новые car-фото в PNG/JPG без WebP-пути — находка.
6. **`sitemap.xml`, `robots.txt`, `CNAME` — не трогать вслепую.** Это GitHub Pages +
   кастомный домен + SEO одновременно. План, который их перезаписывает/удаляет без
   отдельного объяснения зачем — находка.
7. **Внешняя зависимость — Cloudflare Worker.** Любое изменение формата данных,
   отправляемых формой заявки (имя полей, структура payload), должно явно
   констатировать совместимость с воркером на `odd-meadow-4208.litaufit.workers.dev` —
   сам воркер не в этом репозитории и ревьюер его не видит, так что несовместимость
   молча не всплывёт нигде, кроме прод-формы.
8. **Числа.** Если план ссылается на метрики (конверсия, объём трафика, вес страницы) —
   это измеренные цифры или оценка на глазок? Оценка, выданная за измерение — находка.

## Роль: Абнасм-Прюфер (code-review, после сборки)

При вызове с `scope=dod,quality,security,docs,tests` (или подмножеством) оцениваешь
готовый результат по каждому измерению отдельно, с отдельным вердиктом на измерение:

- **DoD** — реализовано ли то, что было в плане, целиком.
- **Quality** — читаемость, отсутствие дублирования, соответствие стилю репо (ванильный
  HTML/CSS/JS, без фреймворков — это осознанный выбор проекта, не недосмотр).
- **Security** — для статического сайта это в первую очередь: нет ли случайно закоммиченных
  секретов/токенов, нет ли XSS-уязвимых мест при вставке пользовательских данных в DOM
  (особенно в коде форм, который шлёт данные на Worker).
- **Docs** — если менялась логика `generate_cars.py` или формат `CARS`, обновлены ли
  комментарии в самом файле (отдельного docs-репозитория нет, комментарии в коде — это
  и есть документация здесь).
- **Tests** — автотестов в проекте нет (статический сайт). Вместо unit-тестов —
  факт ручной проверки в браузере (мобильная ширина + десктоп) должен быть явно
  зафиксирован в диффе/PR, иначе это находка.

## Кто какой шаг делает

Ролей сверх дефолта плагина нет — `.claudex.yaml` в этом репозитории не создан
намеренно. Правило "кто строил — тот не оценивает" обеспечивает сам плагин
(`claudex-loop`), а не конфиг этого репо.

## Конвенции вызова

- Где лежат планы и логи ревью:
  ```
  /claudex-loop:plan-review
      PLAN_FILE=_plans/ГГГГ-ММ-ДД-<тема>.md
      LOG_FILE=_plans/ГГГГ-ММ-ДД-<тема>-review-log.md
  ```
  `/PLAN.md` и `/PLAN-REVIEW-LOG.md` в корне репо — транзитные рабочие файлы
  (см. `.gitignore`), финальные версии коммитятся в `_plans/`.
- Модель фиксируется ролевым конфигом плагина (`gpt-6-sol`/`medium`), не этим файлом.
- Применять `/claudex-loop` имеет смысл для изменений, где ошибка в плане стоит дорого
  позже (новый генератор страниц, смена формата `CARS`, что-то, трогающее SEO/sitemap,
  изменение формата данных к Worker). НЕ для однострочных правок, чисто визуальных
  CSS-правок без структурных последствий, правок текста/контента.
- Платформенные отличия Windows/macOS и детали враппера — `docs/betrieb.md` плагина
  (`claudex-loop`), не дублируются здесь.
